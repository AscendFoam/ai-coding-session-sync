# AI Coding Session Sync 工程化项目推进方案

> 本文基于 [`Codex会话同步方案.md`](./Codex会话同步方案.md) 中的调研结论和当前需求整理，目标是把这个空项目推进成一个可以公开发布、长期维护的开源工具。

## 1. 项目定位

### 1.1 一句话定位

**AI Coding Session Sync 是一个账号无关、provider 无关、同步后端可替换的 AI 编程会话交接与同步工具，面向 Codex、Claude Code 等本地 AI 编程 CLI。**

它不试图破解或替代 Codex / Claude Code 的官方会话机制，也不同步登录态、token、OAuth、API key 等敏感认证信息。它要解决的是更稳定、更普遍的工程问题：

- 同一个项目在多台设备上开发；
- 不同设备可能使用不同 AI 账号、不同模型服务、不同中转站；
- 原生 session 文件不一定能跨设备、跨账号、跨 provider 可靠恢复；
- 但用户仍然希望另一台设备上的 AI 助手快速理解当前上下文、代码状态、已完成工作和下一步任务。

因此项目的主线应当从“原样同步原生 session 并恢复同一个会话”调整为：

**同步项目绑定的上下文包，在另一台机器上新开或恢复 AI 会话时自动注入高质量交接信息；在可行时再提供原生 session 文件同步作为实验能力。**

### 1.2 目标用户

- 同时使用 Mac / Windows / Linux 多台设备的开发者。
- 一台设备使用官方 Codex，另一台设备使用自定义中转站或企业代理的开发者。
- 同时使用 Codex 和 Claude Code，希望它们都能共享项目上下文的开发者。
- 需要在公司电脑、个人电脑、云主机、远程开发机之间交接 AI 编程上下文的开发者。
- 希望把会话交接能力开源、自托管、可审计，而不是依赖某个单一厂商云同步的用户。

### 1.3 非目标

- 不同步 Codex / Claude Code 的认证文件、refresh token、API key、账号配置。
- 不承诺跨账号、跨 provider 原生 `resume` 一定成功。
- 不把内部 session 文件格式当成稳定公开协议。
- 不默认把完整聊天历史公开提交到项目仓库。
- 不实现一个新的 AI coding agent；本项目只做会话上下文提取、归档、同步、导入和交接。

## 2. 核心设计原则

### 2.1 Project-bound

所有同步数据都必须绑定到一个具体项目，而不是全局同步用户目录。项目识别不应只依赖绝对路径，而应综合：

- Git remote URL；
- repo root 相对路径；
- 当前分支；
- HEAD commit；
- 可选的手动 project id；
- 本地路径映射。

这样同一个仓库在不同设备上的路径即使分别是：

```text
/Users/me/code/project
D:\code\project
/home/dev/work/project
```

也能被识别为同一个项目。

### 2.2 Account-neutral

同步包中不能包含任何登录态。不同设备可以分别使用：

- 官方 Codex 账号；
- 自定义 OpenAI-compatible provider；
- Claude Code 官方账号；
- Anthropic-compatible proxy；
- 企业内网模型网关。

工具只负责交接上下文，不假设两端账号相同。

### 2.3 Provider-neutral

同步协议不绑定 Codex 或 Claude Code 的内部格式。项目内部先定义统一中间层：

```text
native transcript/session
        ↓ adapter
normalized conversation excerpt
        ↓ summarizer / packer
handoff bundle
        ↓ backend
Git / Gitee / GitLab / object storage / local folder
```

Codex、Claude Code、后续的 Gemini CLI / Cursor / Aider 等都可以通过 adapter 接入。

### 2.4 Handoff-first

主流程优先生成人类和模型都能读懂的交接包，而不是依赖脆弱的原生 session 迁移。

原因：

- 原生 session 格式可能随版本变化；
- 原生 resume 可能依赖账号、provider、工作区状态、本地缓存；
- 原生 transcript 里可能包含绝对路径、工具输出噪音、敏感信息；
- 高质量 handoff 更容易审查、压缩、加密、跨工具复用。

### 2.5 Security-by-default

默认策略应该保守：

- 默认不同步 auth、token、`.env`、SSH key、云凭证；
- 默认不上传附件、大文件、图片、日志；
- 默认生成同步前预览；
- 默认将完整 transcript 视为敏感数据；
- 支持加密后再同步；
- 明确给出 `doctor` 和 `redact` 检查。

### 2.6 Backend-pluggable

同步后端不应写死为 GitHub。第一阶段支持本地 Git remote 即可，因为 GitHub、Gitee、GitLab、自建 Forgejo 本质上都能通过 Git 使用。后续再扩展：

- local folder；
- bare Git repo；
- GitHub；
- Gitee；
- GitLab；
- S3 / R2 / GCS；
- WebDAV；
- Syncthing / iCloud / OneDrive sidecar folder。

## 3. 推荐产品形态

### 3.1 项目名称

当前仓库名是 `ai-coding-session-sync`。CLI 可以使用更短的命令名：

```bash
aiss
```

含义：AI Session Sync。

也可以提供语义更明确的长命令别名：

```bash
ai-session-sync
```

### 3.2 两种工作模式

#### Stable Handoff Mode

这是默认模式，也是项目的核心价值。

它生成一个项目级同步包。逻辑上一次 snapshot 会包含 handoff、excerpt、patch 和 manifest；物理目录建议和第 4.1 节保持一致，例如：

```text
.ai-session-sync/
  config.toml
  manifests/
    <snapshot>.json
  handoffs/
    <snapshot>.md
  excerpts/
    <snapshot>.jsonl
  patches/
    <snapshot>.patch
  latest/
    codex.json
    claude.json
```

另一台机器导入后不强求原生 resume，而是生成或自动注入 bootstrap prompt，让 Codex / Claude Code 在当前机器的新会话里接上工作。

#### Experimental Native Mode

这是高级模式，主要给愿意承担风险的用户。

它可以同步部分原生 session/transcript 文件：

```text
.ai-session-sync/native/
  codex/
    sessions/
  claude/
    projects/
```

但必须明确标注：

- 不保证跨账号恢复；
- 不保证跨 provider 恢复；
- 不保证未来版本兼容；
- 默认不同步认证文件；
- 一旦路径不一致，需要 path remap；
- 出错时自动降级到 handoff mode。

## 4. 同步包协议设计

### 4.1 目录布局

建议采用项目本地 sidecar 目录：

```text
.ai-session-sync/
  config.toml
  manifests/
    20260423T151230Z-macbook-codex.json
  handoffs/
    20260423T151230Z-macbook-codex.md
  excerpts/
    20260423T151230Z-macbook-codex.jsonl
  patches/
    20260423T151230Z-macbook-codex.patch
  native/
    codex/
    claude/
  locks/
  tmp/
```

为了避免污染业务仓库，可以支持三种存储策略：

- `in-repo`：直接把 `.ai-session-sync/` 提交到项目仓库，适合个人私有项目。
- `sidecar-repo`：把同步包提交到单独的同步仓库，业务仓库只保存 `.ai-session-sync/config.toml`。
- `ignored-local`：`.ai-session-sync/` 加入 `.gitignore`，由工具自己 push/pull 到远端。

推荐默认值：

```text
业务代码私有且只有自己使用：in-repo
业务代码可能公开或多人协作：sidecar-repo
存在敏感项目上下文：sidecar-repo + encryption
```

### 4.2 Manifest Schema

`manifest.json` 是每次导出的索引和一致性检查依据。

示例：

```json
{
  "schema_version": "0.1.0",
  "snapshot_id": "20260423T151230Z-macbook-codex",
  "created_at": "2026-04-23T15:12:30+08:00",
  "project": {
    "id": "ai-coding-session-sync",
    "root_hint": ".",
    "git_remote": "git@github.com:owner/ai-coding-session-sync.git",
    "branch": "main",
    "head": "abc1234",
    "dirty": true
  },
  "source": {
    "tool": "codex",
    "tool_version": "unknown",
    "provider_profile": "local-official",
    "device_id": "macbook-pro",
    "os": "macos"
  },
  "artifacts": {
    "handoff": "handoffs/20260423T151230Z-macbook-codex.md",
    "recent_turns": "excerpts/20260423T151230Z-macbook-codex.jsonl",
    "patch": "patches/20260423T151230Z-macbook-codex.patch",
    "native": []
  },
  "redaction": {
    "enabled": true,
    "ruleset": "default",
    "warnings": []
  },
  "compatibility": {
    "import_strategy": "handoff",
    "native_resume_supported": "unknown"
  }
}
```

### 4.3 Handoff Template

`handoff.md` 是最重要的产物。建议模板：

```markdown
# Session Handoff

## Current Goal

当前任务目标。

## Project State

- Repository:
- Branch:
- HEAD:
- Dirty worktree:

## Completed Work

- 已完成事项。

## Important Decisions

- 关键设计决策和原因。

## Relevant Files

- `path/to/file`: 为什么相关。

## Open Questions

- 仍未确定的问题。

## Next Steps

1. 下一步。
2. 再下一步。

## Constraints

- 不能违反的约束。

## Verification

- 已跑过的测试或尚未验证的部分。
```

### 4.4 Normalized Conversation Excerpt

`recent_turns.jsonl` 不保存完整原生 transcript，而是保存经过清洗、压缩、路径归一化后的重要片段。

示例：

```jsonl
{"role":"user","created_at":"2026-04-23T15:01:00+08:00","text":"希望实现 Codex 与 Claude Code 的跨设备会话同步。"}
{"role":"assistant","created_at":"2026-04-23T15:03:00+08:00","text":"建议采用 handoff-first，不依赖跨账号原生 resume。"}
```

处理规则：

- 只保留最近 N 轮或重要片段；
- 默认删除工具长输出；
- 默认替换本机绝对路径为 `${PROJECT_ROOT}`；
- 默认删除疑似 token、cookie、key、`.env` 内容；
- 可以保留用户标记为 `important` 的决策。

### 4.5 Patch Artifact

如果工作区有未提交修改，导出：

```bash
git diff --binary > patches/<snapshot>.patch
```

同时可以记录：

```bash
git status --short
```

导入时提供三种策略：

- `check-only`：只提示有 patch，不自动应用；
- `apply`：执行 `git apply --3way`；
- `branch`：创建临时分支后应用 patch。

推荐默认：`check-only`，避免破坏当前工作区。

## 5. Codex 适配方案

### 5.1 读取范围

Codex adapter 需要优先支持：

- 识别 `CODEX_HOME`；
- 未设置时读取默认 `~/.codex`；
- 扫描 sessions/transcripts；
- 根据当前项目路径、repo 信息、最近活跃时间筛选候选会话；
- 提取最近用户目标、助手总结、文件路径、命令、待办。

### 5.2 同步边界

必须明确排除：

```text
auth.json
config.toml 中的敏感 provider key
logs 中疑似 token 的内容
缓存、索引、大文件
```

项目级 `.codex/config.toml` 可以由用户自行提交，但本工具不应默认复制全局 Codex 配置。

### 5.3 导入策略

Codex 导入时生成 bootstrap prompt：

```text
请继续这个项目。你正在从另一个设备的 AI coding 会话交接过来。

以下是项目交接信息：
[handoff.md]

以下是最近对话摘录：
[recent_turns.jsonl rendered]

当前本机环境可能使用不同 Codex 账号或 provider。不要假设可以恢复原生 session。
请先确认你理解的当前状态、未完成事项和下一步计划，然后继续工作。
```

命令层可以提供：

```bash
aiss import --tool codex --print-prompt
aiss import --tool codex --write-prompt .ai-session-sync/bootstrap.codex.md
aiss import --tool codex --launch
```

`--launch` 可以在 MVP 之后再做，因为不同 Codex 版本的启动参数可能变化。MVP 先保证 prompt 文件可靠生成。

## 6. Claude Code 适配方案

### 6.1 读取范围

Claude Code adapter 需要优先支持：

- 扫描 `~/.claude/projects/`；
- 读取项目相关 JSONL transcript；
- 读取 `~/.claude/history.jsonl` 中和项目有关的命令历史；
- 可选读取项目 memory；
- 可选读取项目 `CLAUDE.md`；
- 可选读取 `.claude/settings` 或 rules，但必须先做敏感信息检查。

### 6.2 路径重映射

Claude Code 社区工具普遍遇到的难点是：本地会话常按绝对路径组织。两台设备路径不同，就算 session 文件同步过去，也可能无法原生 resume。

因此本项目应该把 path remap 作为核心能力，而不是后期补丁。

`path_map.toml` 示例：

```toml
[project]
id = "ai-coding-session-sync"
canonical_root = "${PROJECT_ROOT}"

[[devices]]
device_id = "macbook-pro"
root = "/Users/qinchaoyang/Desktop/PC/codes/local/ai-coding-session-sync"

[[devices]]
device_id = "windows-pc"
root = "D:/codes/local/ai-coding-session-sync"
```

在 handoff mode 中，路径统一渲染为 `${PROJECT_ROOT}/path/to/file`。

在 native mode 中，可以尝试：

- 将原路径 slug 映射到当前设备路径 slug；
- 重写 transcript 中安全可替换的路径字段；
- 保留原文件备份；
- 失败则降级到 handoff prompt。

### 6.3 同步边界

必须默认排除：

```text
credentials
OAuth token
API key
settings 中疑似密钥字段
MCP server secret
shell history 中疑似 secret
大型附件
```

Claude Code 的 memory / settings / skills 是否同步，应设计成 profile：

```text
minimal: 只同步 handoff + recent turns + patch
project: minimal + CLAUDE.md + 项目 memory
native: project + 原生 JSONL session
full: native + settings/skills/rules，但需要显式确认和加密
```

这里建议明确三组概念，避免后续实现和文档混淆：

- `storage`：同步包放在哪里，例如 `in-repo`、`sidecar-repo`、`ignored-local`。
- `mode`：同步策略走 handoff 还是 native，例如 `handoff`、`native`。
- `profile`：同步内容范围，例如 `minimal`、`project`、`native`、`full`。

也就是说：

- `storage` 决定位置；
- `mode` 决定导入/恢复路径；
- `profile` 决定打包粒度。

## 7. CLI 设计

### 7.1 命令概览

```bash
aiss init
aiss status
aiss export
aiss import
aiss push
aiss pull
aiss sync
aiss inspect
aiss doctor
aiss redact
aiss config
```

### 7.2 初始化

```bash
aiss init --tool codex --backend git
aiss init --tool claude --backend git
aiss init --tool codex,claude --backend git --storage sidecar-repo
```

初始化内容：

- 创建 `.ai-session-sync/config.toml`；
- 设置 project id；
- 检测 Git remote；
- 生成 device id；
- 设置默认 profile；
- 生成 `.gitignore` 建议；
- 检查 Codex / Claude Code 本地目录是否存在。

### 7.3 导出

```bash
aiss export --tool codex
aiss export --tool claude
aiss export --tool all --include-patch
aiss export --tool claude --mode native
```

导出流程：

1. 识别 repo root。
2. 读取本地配置。
3. 检查工作区状态。
4. 扫描对应工具的本地 session。
5. 选择最近或指定 session。
6. 生成 normalized excerpts。
7. 生成 handoff。
8. 生成 patch。
9. 执行 redaction。
10. 写入 manifest。
11. 输出下一步建议。

### 7.4 导入

```bash
aiss import --tool codex
aiss import --tool claude --snapshot latest
aiss import --tool codex --apply-patch
aiss import --tool claude --native --fallback handoff
```

导入流程：

1. 拉取或读取远端同步包。
2. 校验 project id / Git remote / branch / HEAD。
3. 提示当前工作区是否有冲突风险。
4. 可选应用 patch。
5. 生成 bootstrap prompt。
6. 可选写入工具约定位置。
7. 可选尝试 native session remap。
8. 输出用户下一步命令。

### 7.5 同步

```bash
aiss sync --tool all
```

等价于：

```text
pull -> export -> conflict check -> push
```

为了避免覆盖，所有 snapshot 都应 immutable。`latest` 只是一枚指针，可以更新；历史快照不覆盖。

### 7.6 检查

```bash
aiss doctor
```

检查内容：

- 当前是否在 Git repo 中；
- 同步目录是否存在；
- Codex / Claude Code 本地目录是否存在；
- 是否存在疑似敏感文件；
- Git remote 是否可用；
- 当前路径是否已注册到 path map；
- 当前设备是否配置 encryption key；
- 最近同步包是否能解析。

## 8. 配置设计

`.ai-session-sync/config.toml` 示例：

```toml
schema_version = "0.1.0"
project_id = "ai-coding-session-sync"
storage = "sidecar-repo"

[backend.git]
remote = "git@github.com:owner/ai-coding-session-sync-state.git"
branch = "main"

[tools.codex]
enabled = true
mode = "handoff"
codex_home = "auto"
include_native = false

[tools.claude]
enabled = true
mode = "handoff"
claude_home = "auto"
include_native = false
include_memory = true

[redaction]
enabled = true
ruleset = "default"

[encryption]
enabled = false
provider = "age"
```

本机私有配置放在：

```text
.ai-session-sync/local.toml
```

并默认加入 `.gitignore`。

`local.toml` 可以保存：

- device id；
- 本机项目路径；
- 本机 Codex / Claude Code home；
- 本机 provider profile 名称；
- encryption identity path。

## 9. 同步后端设计

### 9.1 Git Backend

第一阶段只需要把 Git 当作通用同步后端，不需要直接调用 GitHub API。

能力：

- `git init` sidecar repo；
- `git remote add`；
- `git pull --rebase`；
- 写入 snapshot；
- `git add/commit/push`；
- 冲突时保留双方 snapshot；
- 支持 GitHub / Gitee / GitLab / 自建 Git。

设计要点：

- 不强制用户把同步包放入业务 repo；
- commit message 机器生成即可；
- snapshot 不覆盖；
- `latest.json` 更新冲突时按时间和 device id 合并；
- 对公开仓库强提示风险。

### 9.2 Local Folder Backend

适合 Syncthing、iCloud、OneDrive、坚果云等外部同步工具。

```bash
aiss init --backend local --path ~/Sync/ai-session-sync
```

### 9.3 Object Storage Backend

后续支持：

- S3；
- Cloudflare R2；
- GCS；
- MinIO。

对象路径：

```text
projects/<project_id>/snapshots/<snapshot_id>/manifest.json
```

## 10. 安全与隐私

### 10.1 永不默认同步的内容

```text
~/.codex/auth.json
~/.claude 中的 credentials / token / OAuth 数据
.env
.env.*
id_rsa / id_ed25519
*.pem
*.key
cloud provider credentials
cookies
browser storage
node_modules
.venv
dist / build
large binary artifacts
```

### 10.2 Redaction Engine

MVP 需要支持：

- 常见 token 正则；
- OpenAI / Anthropic / GitHub token 模式；
- AWS / GCP / Azure key 模式；
- `.env` 行级过滤；
- 用户自定义 denylist；
- 路径归一化；
- 同步前 diff 预览。

### 10.3 加密

建议第二阶段支持 `age`：

```bash
aiss config encryption enable --recipient age1...
aiss export --encrypt
```

也可以支持 passphrase 模式，但更推荐 public-key recipient，方便多设备。

### 10.4 风险提示

用户首次初始化时必须明确告知：

- AI 会话可能包含源码、命令输出、错误日志和敏感信息；
- 如果同步到公开 GitHub 仓库，等同于公开这些内容；
- 原生 transcript 比 handoff 更敏感；
- 开启 native/full profile 前建议启用加密。

## 11. 冲突处理

### 11.1 Snapshot 不可变

每次 export 生成新 snapshot，不覆盖旧文件。

```text
20260423T151230Z-macbook-codex
20260423T152010Z-windows-codex
20260423T153300Z-macbook-claude
```

### 11.2 Latest 指针可合并

维护：

```text
latest/codex.json
latest/claude.json
latest/all.json
```

如果两个设备同时更新，保留两个候选：

```json
{
  "candidates": [
    "20260423T151230Z-macbook-codex",
    "20260423T152010Z-windows-codex"
  ],
  "requires_selection": true
}
```

用户导入时选择：

```bash
aiss import --snapshot 20260423T152010Z-windows-codex
```

### 11.3 Patch 冲突

导入 patch 前必须检查：

- 当前工作区是否 clean；
- HEAD 是否匹配 manifest；
- 是否跨分支；
- patch 是否能 `--check`。

失败时不自动覆盖，输出：

- 冲突原因；
- patch 路径；
- 建议命令；
- handoff prompt 仍可使用。

## 14. MVP 范围

### 14.1 MVP 必须有

- `aiss init`
- `aiss status`
- `aiss export --tool codex`
- `aiss export --tool claude`
- `aiss import --tool codex --print-prompt`
- `aiss import --tool claude --print-prompt`
- 生成 `manifest.json`
- 生成 `handoff.md`
- 生成 `recent_turns.jsonl`
- 可选生成 `changes.patch`
- 默认 redaction
- local folder backend
- Git backend 的基本 push/pull
- path normalization
- 基础测试和 fixture

### 14.2 MVP 暂不做

- 自动调用 AI 模型总结完整历史；
- 自动启动 Codex / Claude Code；
- 原生 session 恢复保证；
- GUI；
- 常驻 daemon；
- VS Code 插件；
- 多人协作权限系统；
- 复杂云存储后端。

### 14.3 MVP 成功标准

在你的真实场景中通过：

1. Mac 上使用官方 Codex，在项目 A 中执行 `aiss export --tool codex --include-patch`。
2. 同步到 GitHub 或 Gitee。
3. Windows 上使用中转站 Codex，执行 `aiss import --tool codex --print-prompt`。
4. 新 Codex 会话读取 prompt 后能准确接续任务。
5. 反向从 Windows 导出，再由 Mac 导入。
6. Claude Code 也能完成同样的 handoff 流程。
7. 全流程不需要复制 auth，不要求两边账号一致。

## 16. 与现有工具的差异化

这个项目不应该只是“再做一个同步 `~/.claude/` 的脚本”。更强的开源定位是：

| 维度 | 常见 Claude-only 同步工具 | 本项目 |
| --- | --- | --- |
| 支持对象 | 主要 Claude Code | Codex + Claude Code，后续可扩展 |
| 同步目标 | 原生 JSONL / settings | handoff-first + native optional |
| 跨账号 | 通常不是核心卖点 | 核心设计目标 |
| 跨 provider | 通常不是核心卖点 | 核心设计目标 |
| 绝对路径问题 | 常作为限制 | path remap 是核心能力 |
| 后端 | Git / S3 / iCloud 等单一实现 | backend-pluggable |
| 安全模型 | 视项目而定 | security-by-default |
| 公开仓库适配 | 风险较高 | 推荐 sidecar + encryption |

## 18. 关键风险

### 18.1 上游内部格式变化

Codex / Claude Code 的本地 session 文件都不是为本项目设计的稳定协议。应对方式：

- adapter 做容错；
- fixtures 做版本记录；
- native mode 标注 experimental；
- handoff mode 保持主流程。

### 18.2 敏感信息泄漏

AI coding 会话可能包含源码、日志、路径、环境变量、命令输出。应对方式：

- 默认 redaction；
- 默认最小同步；
- native/full profile 需要显式确认；
- 支持加密；
- 文档反复提示公开仓库风险。

### 18.3 Patch 破坏工作区

应对方式：

- 默认不自动 apply；
- apply 前要求 clean worktree 或显式 `--force`；
- 优先 `git apply --check`；
- 支持创建临时分支。

### 18.4 用户误以为等价于原生 resume

应对方式：

- README 中明确概念；
- 命令输出使用 “handoff/import prompt” 而不是 “restore session”；
- native 功能单独放到 experimental 命名空间。

## 19. README 首屏建议

README 首屏应该直接说明：

```markdown
# AI Session Sync

Sync project-bound AI coding context across devices, accounts, and providers.

Works with Codex and Claude Code by exporting a safe handoff bundle instead of relying on fragile cross-machine native session resume. Native transcript sync is available as an experimental option.
```

然后给出 30 秒示例：

```bash
aiss export --tool codex --include-patch
aiss push

# on another machine
aiss pull
aiss import --tool codex --print-prompt
```

README 必须尽早放出安全警告：

```markdown
Do not sync auth files. Do not publish raw transcripts unless you understand the risk. Use encryption for private work.
```

## 20. 下一步建议

推荐接下来按这个顺序推进：

1. 初始化开源项目骨架：README、LICENSE、pyproject、基础 CLI。
2. 先实现 `handoff.md + manifest.json + import prompt`，不急着碰原生 session。
3. 用你自己的 Mac 官方 Codex 和 Windows 中转站 Codex 做第一条真实闭环。
4. 再接 Claude Code adapter，重点解决路径归一化。
5. 最后才做 native experimental 和加密发布。

最小可用版本不需要完美解析所有历史。只要能可靠生成一个高质量 handoff，并让另一台设备的新 AI 会话准确接上工作，这个项目就已经解决了最核心的问题。
